# tianhaoluo.com

Personal website of **Tianhao Luo** — Harvard PhD candidate in Biomedical Informatics and NSF Graduate
Research Fellow working on AI for science.

Live at **https://tianhaoluo.com**, served by GitHub Pages from the `main` branch of this repository.

## Structure

The site is a single self-contained page. All CSS lives in one `<style>` block in `<head>`, and the
behaviour script in one `<script>` block before `</body>`. There is no build step, no bundler, and no
framework — edit `index.html`, push to `main`, and the change is live.

```
index.html     the entire site: markup, styles, and behaviour
profile.json   schema.org JSON-LD entity graph (mirrors the inline @graph)
llms.txt       markdown profile for AI agents and crawlers
robots.txt     crawler directives; open to all search and AI crawlers
sitemap.xml    sitemap
CNAME          custom domain
*.jpg / *.png  photos, advisor headshots, and institution logos
```

External requests are Google Fonts (DM Serif Display / Outfit / JetBrains Mono) and Font Awesome.

## Design

Light paper, DM Serif Display headings, one blue accent (`--accent`). Colour and type are CSS custom
properties in `:root` — **change the tokens, not the rules.**

**The hero is a WebGL stage** (the `SCALES` block in the behaviour script). One set of roughly 22,000
lit beads is re-formed in turn into the photo, a DNA double helix, a cutaway cell, a tissue section,
and a patient — the scales a multiscale world model connects. A small coral subset keeps its colour
throughout (variant → nucleolus → tumour focus → lesion). The typed phrase in the tagline and the
scale bar under the stage follow the same sequence. Scrolling past the hero disperses the beads into a
sparse field that drifts behind the rest of the page.

- It is raw WebGL2 in one draw call; there is no 3D library and no build step.
- To retime, reorder, or re-pose a scale, edit the `STAGES` array. To recolour, edit the palette `C`.
  Each model is generated by its own `gen…()` function.
- The photo stage samples `grad.JPG` through a canvas, so it needs the page served over http(s).
  Preview with `python3 -m http.server`, not by opening the file directly.
- `.stage-slot` is both the photo's box and the anchor the stage measures. If you change its aspect
  ratio, change `ASPECT` in the script to match.
- Without WebGL2, or under `prefers-reduced-motion`, none of it runs and the hero is simply the photo.
  All other motion (hero entrance, heading and image reveals, card tilt) is disabled under
  `prefers-reduced-motion` too.

## Editing

**Sections** appear in this order: hero, about, news, education, research, industry, publications,
teaching, contact. Section numbering is a CSS counter. If you add a section, give the `<section>` an
`id` and add it to the nav and the mobile menu.

**Adding a news item** — copy a `.news-item` block to the top of `.news-list`, then move the `is-new`
class off the previous top item onto the new one. Only the most recent entry should carry it.

**Adding images** — resize before committing. Photos should be no more than ~1400px on the long edge,
headshots and logos no more than 200px. Oversized images are the main thing that slows this page down.
On macOS: `sips -Z 1200 -s format jpeg -s formatOptions 82 in.jpg --out out.jpg`.

**Facts live in three places.** If you change a role, date, or affiliation, update `index.html`, the
inline JSON-LD `@graph`, and `llms.txt` together, and mirror the graph into `profile.json`. They are
what search engines and AI assistants read; if they disagree with the page, the page loses authority.

## Publishing

```bash
git add -A
git commit -m "describe the change"
git push
```

GitHub Pages rebuilds automatically — usually live within a minute, plus up to ten minutes of CDN
caching.
